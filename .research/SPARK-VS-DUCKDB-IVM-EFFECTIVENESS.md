## Overhead-dominated check (CP4)

- `sum_model_time` for spark-openivm batch 2 = 859.8s; `total_batch_time` = 181.8s.
- `overhead_ratio = (total - sum_model_time) / total = -3.73`. Because dbt ran models concurrently, summed model time exceeds wall-clock, so the CP4 formula does **not** show `> 0.5` overhead dominance.
- `no_pending_deltas` refresh outcomes found in Spark driver logs = 36 across batch-2/3 refresh logs, below the "half of refreshes" threshold if spread across 49 MVs per batch.
- Verdict: **not proven overhead-dominated by CP4**, but the overall Phase-8 comparison gate is still unusable because DuckDB did not produce valid incremental batches. This report therefore uses terminal **R0 benchmark-gate failure** and avoids assigning R1-R5 as primaries.
- Validation was after the timed dbt window in the benchmark-server log: batch completion timestamps follow validation messages, while `run-*.json.duration_s` captures the dbt run window separately.
